自前の Hyperliquid ノードを運用するチームは、マーケットデータをピアに依存しています。パブリックな gossip ピアは接続枠が限られ、予告なく切断され、負荷が高まると性能が低下します。ネットワークアップグレードの前後では特に顕著です。

<Note>
  **Direct Sentry Peering は、お客様のノードと、当社バリデータと同一拠点に配置された Hyperdash セントリーインフラを結ぶ、ホワイトリスト方式のプライベート接続です。** 1 ホップで直結し、間に中継層はありません。
</Note>

## 対象となるチーム

自前の非バリデータ Hyperliquid ノードをすでに運用している、または運用を予定しており、安定した経路を求めるチーム向けです。

- マーケットメイカーおよびレイテンシに敏感なトレーディングファーム
- クオンツファンド、リサーチファンド
- データ・アナリティクスプロバイダー
- Hyperliquid 上で開発を行うインフラチーム

## ピアリングかホスト型フィードか

セントリーピアリングは配信レイヤーそのものを取り除きます。ホスト型フィードは、データがお客様に届くまでに必ず受信、処理、再配信の各段階を経ます。直接ピアリングであれば、お客様のノードが Hyperliquid ネイティブの gossip プロトコルでブロックを受信し、デコードはローカルで行います。

ピアリングは、すでに自前のノードを運用しているチームに適しています。ノードの運用を避けたい場合は、API によるアクセスについてご相談ください。

## 提供内容

- Hyperliquid ネイティブの gossip プロトコルによる**ブロックとステート更新**
- **メンプールトランザクション。** 当社インフラは `split_client_blocks` を一貫して実行しているため、お客様のノードで `mempool_txs` が生成されます
- **ホワイトリスト登録された 3 つの IP。** 共有枠ではなく、お客様のノード専用に確保されます
- **追加の IP とリージョン**もご要望に応じて提供。ステージングから本番への移行時に、再オンボーディングは不要です

当社がお客様の執行経路に入ることは一切ありません。注文の送信は Hyperliquid の API に直接届きます。

## 事前準備

お客様が運用する非バリデータの Hyperliquid ノードと、静的なパブリック IP を持つマシンが必要です。ハードウェア、OS、ポートの要件は当社ではなく Hyperliquid が定めています。最新の仕様は [Hyperliquid ノードリポジトリ](https://github.com/hyperliquid-dex/node) をご確認ください。

メンプールの取得を有効化する前に、ディスクと帯域を十分に見積もってください。`mempool_txs` は継続的に書き込まれ、ブロックデータのみの場合と比べてデータ量が大幅に増加します。

## セットアップ

<Steps>
  <Step title="ホワイトリスト登録">
    お客様のノードの静的 IP をお知らせください。当社のバリデータセントリーノードにホワイトリスト登録し、該当リージョンのセントリー IP をご返送します。
  </Step>
  <Step title="設定">
    `~/override_gossip_config.json` の gossip オーバーライド設定で、当社のセントリー IP をルートエントリとして指定します。

    ```json
    {
      "root_node_ips": [{ "Ip": "<sentry-ip-we-provide>" }],
      "try_new_peers": false,
      "chain": "Mainnet"
    }
    ```

    `try_new_peers` を `false` にすることで、ノードがパブリックピアへ戻ってしまうことなく、確保されたピアに接続し続けます。
  </Step>
  <Step title="有効化">
    ノードを再起動し、ブロックが適用されていることを確認してください。これで、高速かつ安定した常時接続が有効になります。
  </Step>
</Steps>
