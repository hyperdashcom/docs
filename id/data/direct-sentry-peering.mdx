Tim yang menjalankan node Hyperliquid sendiri bergantung pada peer untuk data pasar. Peer gossip publik memiliki kapasitas terbatas, terputus tanpa pemberitahuan, dan menurun kinerjanya saat beban tinggi, terutama di sekitar pemutakhiran jaringan.

<Note>
  **Direct Sentry Peering adalah koneksi privat dengan daftar putih antara node Anda dan infrastruktur sentry Hyperdash, yang ditempatkan bersama validator kami.** Satu hop, tanpa lapisan perantara.
</Note>

## Untuk siapa layanan ini

Untuk tim yang sudah menjalankan, atau siap menjalankan, node Hyperliquid non-validator sendiri dan menginginkan jalur yang stabil ke jaringan:

- Market maker dan firma trading yang sensitif terhadap latensi
- Dana kuantitatif dan riset
- Penyedia data dan analitik
- Tim infrastruktur yang membangun di atas Hyperliquid

## Peering atau feed terkelola

Sentry peering menghilangkan lapisan distribusi sepenuhnya. Feed terkelola mana pun harus menerima, memproses, dan menyiarkan ulang data sebelum sampai kepada Anda. Dengan peering langsung, node Anda menerima blok melalui protokol gossip asli Hyperliquid dan Anda melakukan decoding secara lokal.

Peering cocok untuk tim yang sudah menjalankan node sendiri. Jika Anda lebih memilih tidak mengoperasikannya, mari bicarakan akses API sebagai gantinya.

## Yang Anda dapatkan

- **Blok dan pembaruan state** melalui protokol gossip asli Hyperliquid
- **Transaksi mempool.** Infrastruktur kami menjalankan `split_client_blocks` secara menyeluruh, sehingga `mempool_txs` terisi di node Anda
- **Tiga IP dalam daftar putih**, dicadangkan untuk node Anda, bukan kapasitas bersama
- **IP dan region tambahan** atas permintaan, sehingga Anda bisa berpindah dari staging ke produksi tanpa proses onboarding ulang

Kami tidak pernah berada di jalur eksekusi Anda. Pengiriman order langsung menuju API Hyperliquid.

Peningkatan sebenarnya bergantung pada infrastruktur, region, dan alur pemrosesan Anda sendiri, sedangkan latensi pada lapisan gossip ditentukan oleh jaringan.

## Sebelum memulai

Anda memerlukan node Hyperliquid non-validator yang Anda operasikan sendiri, pada mesin dengan IP publik statis. Persyaratan perangkat keras, sistem operasi, dan port ditetapkan oleh Hyperliquid, bukan oleh kami: lihat [repositori node Hyperliquid](https://github.com/hyperliquid-dex/node) untuk spesifikasi terkini.

Perhitungkan kapasitas disk dan bandwidth untuk penangkapan mempool sebelum mengaktifkannya. `mempool_txs` ditulis terus-menerus dan jauh lebih besar dibandingkan data blok saja.

## Penyiapan

<Steps>
  <Step title="Daftar putih">
    Kirimkan IP statis node Anda kepada kami. Kami memasukkannya ke daftar putih pada sentry validator kami dan mengirimkan kembali IP sentry untuk region Anda.
  </Step>
  <Step title="Konfigurasi">
    Tetapkan IP sentry kami sebagai entri root pada konfigurasi override gossip Anda, di `~/override_gossip_config.json`:

    ```json
    {
      "root_node_ips": [{ "Ip": "<sentry-ip-we-provide>" }],
      "try_new_peers": false,
      "chain": "Mainnet"
    }
    ```

    Menyetel `try_new_peers` ke `false` menjaga node Anda tetap pada peer yang dicadangkan alih-alih kembali ke peer publik.
  </Step>
  <Step title="Aktivasi">
    Mulai ulang node Anda dan pastikan blok diterapkan. Anda kini aktif pada koneksi yang cepat, stabil, dan selalu tersedia.
  </Step>
</Steps>
