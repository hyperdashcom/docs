## 对等连接还是托管数据源

哨兵对等连接彻底移除了数据分发层。任何托管数据源都必须先接收、处理并重新广播数据，才能送达您手中。使用直连对等，您的节点通过 Hyperliquid 原生 gossip 协议接收区块，并在本地完成解码。

对等连接适合已经在运行自有节点的团队。如果您不希望自行运维节点，欢迎与我们沟通 API 接入方案。

## 服务内容

- **区块与状态更新**，通过 Hyperliquid 原生 gossip 协议传输
- **内存池交易。** 我们的基础设施完整运行 `split_client_blocks`，因此您的节点上会写入 `mempool_txs`
- **三个白名单 IP**，为您的节点专属保留，而非共享容量
- **更多 IP 与区域**可按需开通，方便您从测试环境迁移到生产环境，无需重新接入

我们永远不在您的执行路径上。订单提交直接发往 Hyperliquid 的 API。

## 准备工作

您需要一个由自己运维的非验证 Hyperliquid 节点，部署在具备静态公网 IP 的机器上。硬件、操作系统与端口要求由 Hyperliquid 规定，而非由我们规定：最新配置请参见 [Hyperliquid 节点仓库](https://github.com/hyperliquid-dex/node)。

启用内存池采集前，请先按需规划磁盘与带宽。`mempool_txs` 会持续写入，数据量远大于单纯的区块数据。

## 配置步骤

<Steps>
  <Step title="加入白名单">
    将您节点的静态 IP 发送给我们。我们会将其加入验证者哨兵节点的白名单，并返回对应区域的哨兵 IP。
  </Step>
  <Step title="配置">
    在 `~/override_gossip_config.json` 中，将我们的哨兵 IP 设为 gossip 覆盖配置的根节点：

    ```json
    {
      "root_node_ips": [{ "Ip": "<sentry-ip-we-provide>" }],
      "try_new_peers": false,
      "chain": "Mainnet"
    }
    ```

    将 `try_new_peers` 设为 `false`，可让您的节点保持在专属对等节点上，而不会重新漂移回公共节点。
  </Step>
  <Step title="启用">
    重启节点并确认区块正常应用。至此，您已接入一条快速、稳定、始终在线的连接。
  </Step>
</Steps>
